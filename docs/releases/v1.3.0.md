# Wardryx 1.3.0

A policy can now name the only tools its agents may use. The change is additive:
a policy that does not set `allow_tool` decides, and keeps its `PolicyVersion`,
exactly as before.

## Added

- **`allow_tool`, the closed list of tools a policy's agents may use (invariant
  29).** A requested tool that the list does not name is denied. The check is
  rule 3 of `Decide`, straight after `deny_tool` and before the chain and cost
  rules, so no approval token can lift it. Matching folds case and surrounding
  space the way `deny_tool` does and nothing looser, so `apply-staff-coupon` is
  not `apply_staff_coupon`. On `/v1/decide` both the tool list and the
  `tool_call` name are checked. When several matched policies set a list, a
  tool must be listed by each of them. An empty or absent list restricts
  nothing. A blank entry is refused at load.
- **`/v1/filter-tools` reports a tool outside the list.** Such a tool comes back
  denied with `rule: "allow_tool"`. A tool the deny-list refuses still reports
  `rule: "deny_tool"`. The route stays experimental.
- **Replay reads the recorded tool call name back.** A recorded denial by an
  allow-list reproduces. Without this it would replay as an allow and be
  reported as a divergence.

## Fixed

- **`deny_tool` reads the tool call's name (invariant 29).** Before this release,
  a request whose tool list was benign was allowed even when its `tool_call.name`
  was on a deny-list, because rule 2 of `Decide` read only the tool list. Rule 2
  now reads the tool list and the call's name, the same set rule 3 reads for
  `allow_tool`. `/v1/filter-tools` is unchanged, since it judges one offered tool
  at a time and carries no tool call.

## Changed

- A request that carries a `tool_call` is never `cacheable` under a matched
  `deny_tool`, for the same reason as `allow_tool`: the call's name is outside the
  agent and tool set a cache is keyed on. A request with no `tool_call` is
  unchanged and stays cacheable.
- A decision under a policy that sets `allow_tool` is never `cacheable`. The
  rule reads the tool call's name, which is per call and is not part of the
  agent and tool set a cache is keyed on.
- `Decide`'s documented order now has 13 items. Rule 3 is new and the rules after
  it are renumbered. The reason strings of the existing rules are unchanged.

## Upgrade notes

- A request whose `tool_call.name` is on a deny-list, but not in its tool list, was
  allowed before this release and is denied now. A caller that sends the same name
  in both places sees no change. The TokenFuse MCP broker sends the same name in
  both places, so its calls decide as before.
- Replay of a recorded allow whose tool call names a denied tool now reports a
  divergence, and `wardryx replay` exits non-zero on it. That is the correct answer:
  the record is a call the deny-list refuses.
- No new environment variable and no new route. `compat/1.0.json` is unchanged:
  `allow_tool` is an additive policy field whose zero value means no restriction.
- A policy without `allow_tool` keeps its `PolicyVersion`, as the golden test
  `TestAPolicyWithoutAllowToolKeepsItsPolicyVersion` holds.
- **Rollback.** A build from before 1.3.0 refuses a policy file that uses
  `allow_tool` at start, with `field allow_tool not found`. That failure is loud.
  A policy stored through `PUT /v1/policies/{id}` is decoded without that check,
  so an older build would drop the list silently and stop restricting the
  agent's tools. Remove `allow_tool` from stored policies before rolling back.
- `PUT /v1/policies` still decodes leniently, as it did before this release, so a
  misspelled key other than `allow_tool` is still dropped there. File load stays
  strict.

## Documentation and tests

- 416 test functions, up from 394. `features/allow-tool.feature` binds 14
  scenarios, and `features/deny-tool-call.feature` binds 4, each to a named test.
- The README policy reference (fields, decision order, decision table, and an
  example) and CLAUDE.md invariants 21 and 29 describe the change.

## Not proven: where it says nothing

- Cache consumers: a request with no tool call under a deny_tool stays cacheable, so
  a cache keyed on agent and tool set alone can still serve that allow to a later
  call whose tool call names a denied tool. This release does not close that. A
  caller must key on whether a tool call is present.
- The TokenFuse broker's behaviour, and that it sends the same name in both places,
  were not checked against this build.
- The rollback path was not run end to end on an older build. The file refusal
  was run on the tree before this change. The stored-policy path is read from
  the source, and only the PUT half of it was run.
- Case folding is deliberate and matches `deny_tool`, so a list naming
  `apply_staff_coupon` also allows `APPLY_STAFF_COUPON`. Whether a backend treats
  two names that differ only in case as the same tool was not checked.
- The Postgres integration suite was not run locally, because no database was
  configured. CI's `integration` job is the check.
- The live run was curl against one policy on loopback. No enforcement point
  (TokenFuse's broker) has been run against this build.
- Staticcheck was run under the go1.27.0 toolchain from the local module cache,
  because the local staticcheck cannot read go1.27.2 export data. CI runs it
  under go1.27.1.
