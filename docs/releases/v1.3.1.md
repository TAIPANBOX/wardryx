# Wardryx 1.3.1

A YAML policy file may hold several documents separated by `---`. Before this
release only the first document was read, and every later one was dropped with
no error. This release loads all of them.

## Fixed

- **Every document of a YAML policy file is loaded (invariant 30).** Each
  document holds one policy or a list of policies, as before, and they load in
  order. A document with nothing in it, such as a separator with nothing after
  it, holds no policy and is skipped. A document that fails to decode fails the
  whole file, and the error names it by position, for example `document 2`. The
  strict field check applies to every document, so a misspelled field in a later
  document is refused rather than dropped. A file with one document keeps its
  `PolicyVersion` byte for byte. A file with several has a version that covers
  every policy it loaded.
- The directory loader and `replay -policy` read files through the same decode,
  so they load every document too.

## Upgrade

A deployment whose policy file has more than one document now enforces the rules
it was silently ignoring. A call that was allowed only because a later document's
deny was dropped can now be denied. A later document's `require_human_above_usd`
or `deny_above_usd` now applies as well. Read your policy files before you
upgrade. A file that no longer loads, because a later document has a misspelled
field or a value of the wrong type, stops `serve` and `check` at start, and the
error names the document.

Policies stored through `PUT /v1/policies/{id}` are JSON and are not affected.

Rolling back to 1.3.0 brings back the silent drop for the same file.

## Not proven

- No live deployment's policy file was read, so how many calls change their
  verdict on upgrade is not known.
- The policy and pdp packages were tested locally, together with the gates in
  `CLAUDE.md`. The Postgres integration suite, `govulncheck` and `gosec` run in
  CI and were not run here. No image was built.
- Load cost was not measured. Each document is decoded again from the start of
  the file, so the work grows with the square of the number of documents. That is
  fine for a handful of documents and was not measured for a large file.
- A `.json` policy file that holds more than one JSON value still loads only the
  first. This release does not change that.
