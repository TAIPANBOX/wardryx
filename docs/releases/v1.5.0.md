# Wardryx 1.5.0

A policy can now name the models its agents may use. The change is additive: a
policy that does not set `allow_models` decides, and keeps its `PolicyVersion`,
exactly as before. These notes are a draft for the tag. Nothing here is tagged.

## Added

- **`allow_models`, the models a policy's agents may use (invariant 34).** A
  request whose `model` matches no entry of a matched list is denied, so an
  agent that switches to a model its policy does not name is refused on that
  call. Entries are model ids or globs in the syntax `target` uses (`*`, `?`),
  matched exactly, with no case or space folding. A model holding a control
  character or invalid UTF-8 matches nothing. When several matched policies set
  a list, the model must be named by each. The rule is rule 8 of `Decide`,
  after `deny_if_unattested` and before `max_steps` and the cost rules, so no
  approval token lifts it. An empty or absent list restricts nothing, and a
  blank entry is refused at load and at `PUT /v1/policies/{id}`.
- **Replay reproduces a model denial.** The model was already recorded with
  every decision; replay puts it back to the PDP.

## Changed

- A decision under a policy that sets `allow_models` is never `cacheable`. The
  model is per call, and an enforcement point's cache keyed on agent and tool
  set would answer a call naming a refused model with an allow it stored for a
  listed one.
- `Decide`'s documented order now has 14 items. The model rule is item 8 and
  the rules after it are renumbered. The reason strings of the existing rules
  are unchanged.

## Upgrade notes

- A request that names no model (scopyx's egress decisions, TokenFuse's MCP
  broker on a tool call) is not restricted by `allow_models`. TokenFuse sends
  `unknown` for a model call whose body names no model, and a list refuses it
  unless it names it.
- No new environment variable and no new route. `compat/1.0.json` is unchanged:
  `allow_models` is an additive policy field whose zero value means no
  restriction.
- **Rollback.** A build from before 1.5.0 refuses a policy file that uses
  `allow_models` at start, which is loud. It reads a policy stored in Postgres
  with a decoder that drops the key, so it would stop restricting models
  silently. Remove `allow_models` from stored policies before rolling back.

## Documentation and tests

- 469 test functions, up from 454. `features/allow-models.feature` binds 10
  scenarios, each to named tests.
- The README policy reference (fields, decision order, decision table, the
  `cacheable` contract, an example) and CLAUDE.md invariants 21, 33 and 34
  describe the change.

## Not proven: where it says nothing

- No live run against TokenFuse: the gateway's body is sent through the real
  handler, not by a running gateway on either door.
- The rule bounds the model a call names, not the one a provider serves.
- A caller that sends no model is not restricted (invariant 26: the enforcement
  point is believed).
