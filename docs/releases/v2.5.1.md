# Wardryx 2.5.1

The policy archive (`WARDRYX_POLICY_ARCHIVE`) can now be read by the group of the account that writes it. Until 2.5.0 the directory was `0700` and every file `0600`, so a console running under another uid than the service got "permission denied" on each file, and `wardryx replay` counted every recorded decision under `not archived`. A directory this process creates is now `0750` and a file it keeps is `0640`: the owner writes, the owner's group reads, no other account can do either. Nothing else changes in behaviour: no decision, approval, token or record format moves, no setting is added or removed, and no name `compat/1.0.json` freezes is removed or renamed.

## Changed since 2.5.0

- #133, `fix(archive): let the group of the writing account read the policy archive`. The directory mode is `0750` and the file mode `0640`. The directory's mode is set after it is made, so a process umask of `027` or `077` does not turn it back into `0700`.

No other commit lies between the 2.5.0 tag and this release.

## Upgrade

Replace the 2.5.0 image with 2.5.1. No setting, stored state or wire format changes.

- **A new archive** gets the new modes with no step from you. The account that runs `wardryx replay` has to be in the group of the account that runs the service, for example through a shared group id on a volume both containers mount.
- **An archive 2.5.0 or earlier already wrote** keeps `0700` and `0600`. This release reads it exactly as before and changes the mode of nothing that exists, the directory included, because widening evidence is the operator's act. New sets kept by 2.5.1 go into that directory as `0640`, but the group cannot reach them until the directory is widened too. To open the whole archive to the group:

  ```sh
  chmod 0750 "$WARDRYX_POLICY_ARCHIVE" && chmod 0640 "$WARDRYX_POLICY_ARCHIVE"/*.json
  ```

- **Write access is not granted to the group.** A policy set that a second account could rewrite after a decision was taken under it is not evidence, so the group gets read only.

**Rollback.** Run the 2.5.0 image again. Files kept as `0640` stay readable by the group, and 2.5.0 reads them and keeps its own at `0600`.
