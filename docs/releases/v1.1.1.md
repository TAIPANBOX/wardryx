# Wardryx 1.1.1

One fix for a policy that said "zero" and was not believed, found on the
2026-09-27 forge lab run, and nothing else on the decision path moves.

## The defect (wardryx#70)

A `PUT /v1/policies/{id}` with `"deny_above_usd": 0` answered 200, the stored
policy came back with no `deny_above_usd` at all, and the agent's next priced
call through the gateway was allowed. Both cost fields were plain numbers with
`omitempty`, so an explicit zero and an absent field decoded to the same value:
"deny everything priced" silently became "no ceiling". `require_human_above_usd`
had the same shape. Separately, a refusal reason printed a ceiling of
$0.000001 as `$0.00` and a threshold of $0.005 as `$0.01`.

## The fix

- **Zero is a value.** `deny_above_usd` and `require_human_above_usd` now tell
  "absent" (no rule, exactly as before) from an explicit `0`, which denies or
  holds any priced call, from a policy file and from `PUT` alike.
- **A reason says the amount the policy holds.** Whole cents print as before
  (`$100.00`); a finer amount prints as itself (`$0.000001`, `$0.005`).

Invariant 22 holds the rule; `features/zero-value-policy-ceilings.feature`
binds its scenarios to tests, each red first against 1.1.0, including the
measured `PUT` end to end over HTTP; four mutants were planted and caught
(zero read as unset again, `>=` for `>`, the field dropped on the `PUT` path
only, two-decimal formatting again); the Postgres half ran in CI.

## Compatibility

No policy that exists today changes meaning: a file or a stored policy that
never wrote a literal `0` has the same `PolicyVersion` as under 1.1.0 (the
starter policies the launchers ship: `da10bac8cf9a` under both). The field
names frozen in `compat/1.0.json` do not move. A 1.1.0 deployment moves to 1.1.1
by moving the image tag.

## Limits

An approval token's own cost ceiling message still rounds to cents
(`ErrTokenCostExceeded`); it is tracked separately. The launchers were not
re-run with this build.
