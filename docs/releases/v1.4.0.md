# Wardryx 1.4.0

A `hold_if_signal` rule can now hold a tool call whose risk signal never arrived.
The change is additive: a rule that does not set `when_absent` decides, and keeps
its `PolicyVersion`, exactly as before. These notes are a draft for the tag.
Nothing here is tagged.

## Fixed

- **A tool call padded past the argument cap could not be held by any signal
  rule (invariant 33).** An enforcement point sends arguments over its cap
  (12 KiB, the same as wardryx's own) as `arguments_truncated: true` with no
  arguments, and a classifier does not answer about a call it cannot read. The
  call then reached `/v1/decide` with no signal, every `hold_if_signal` rule had
  nothing to read, and the call was allowed. A caller could reach that outcome on
  purpose by padding any field the tool tolerates. The same allow followed when
  the signal producer's own budget was spent, when it timed out, and when it was
  down. Measured on the 2026-10-14 range runs on all three ranges: 11,264 bytes of
  arguments carried a signal, 13,312 and 65,536 bytes carried none and were
  allowed.

## Added

- **`when_absent` on `hold_if_signal`, `allow` or `hold`.** With `hold`, a
  request that carries a `tool_call` and no signal of the rule's name, of any
  value, is held for a person. A signal of that name with another value, or under
  the threshold, is present and holds nothing. A request with no `tool_call` is
  never held for a missing signal. The hold is rule 12, after every deny rule and
  the cost gate, so it can turn an allow into a hold and change nothing else. Its
  reason names the policy, the signal, the tool call and, when they were, that
  its arguments were not sent.
- **Only an approval of the call lifts that hold.** A token granted for the held
  call lets it through (once, under the single-use default). A token granted for a
  hold that showed no call does not, and neither does a token for another call.
  `approval.VerifyApprovalTokenBoundToCall` is the check.
- **Replay reproduces the hold from the record.** The record carries the tool
  call, and replay already fed its name back; it now also reaches the hold on a
  missing signal.

## Changed

- `when_absent: deny` is refused at load and at `PUT /v1/policies/{id}`, with the
  sentence that a signal can only hold. Any value other than `allow` or `hold` is
  refused, and so is the key with no value, as null or as anything but text.
- `allow` is stored as the default, so a rule that writes it and a rule that
  leaves the key out have the same `PolicyVersion`.

## Upgrade notes

- Nothing changes until a policy sets `when_absent: hold`. This repository ships
  no policy: a launcher that writes one decides whether its deployment holds on a
  missing signal.
- With `hold`, every tool call the signal producer does not answer waits for a
  person, a producer outage included. Set it where that is the trade wanted.
- **Keep single-use on wherever `when_absent: hold` is set.** A padded call
  carries no arguments, so every padded call to the same tool and target in one
  run has the same digest, and the person approving one cannot see what it does.
  A token granted for one fits the next. Under single-use, the default, it lets
  exactly one through; with `WARDRYX_APPROVAL_SINGLE_USE=false` it lets every
  one through for the token's lifetime.
- No new environment variable and no new route. `compat/1.0.json` is unchanged:
  `hold_if_signal` was never frozen, and `when_absent` is optional.
- **Rollback.** A build from before 1.4.0 refuses a `hold_if_signal` that carries
  `when_absent` wherever its rule decoder reads one, in a policy file and in a
  `PUT` body, because that decoder refuses any key it does not know. A policy file
  with the key fails at start, which is loud. How an older build treats such a
  rule already stored in Postgres was not measured for this release: remove the
  key from stored policies before rolling back.

## Documentation and tests

- 454 test functions, up from 438. `features/hold-when-signal-absent.feature`
  binds 9 scenarios, each to named tests.
- The 200-seed sweep `TestSignalsNeverChangeADenyOrRemoveAHoldOverRandomPolicies`
  now draws `when_absent` at random and compares every decision with the same
  policy without the rule.
- The README's decision order, decision table and typed-signal section, and
  CLAUDE.md invariants 25, 27 and 33, describe the change.

## Not proven: where it says nothing

- A live deployment: the option is exercised through the real handler with the
  broker's body byte for byte, not against a running TokenFuse and typryx.
- The default stays `allow`, so a deployment whose policy does not set `hold` is
  as open to a padded call as before this release.
- An approval of one padded call fits every padded call to the same tool and
  target in the run; single-use limits that to one call, it does not bind the
  approval to the arguments the person never saw.
- A caller that leaves `tool_call` out altogether is decided as a model call and
  is not held for a missing signal (invariant 26: the caller is believed about
  whether a call exists).
